topic: iOS Presentation DI Refactor: Remove UseCases Environment, Use FactoryKit at Composition Boundary
updated: 2026-09-25T15:08
---

- (decision) Remove SwiftUI EnvironmentKey for UseCases aggregate to eliminate global container dependency in Presentation layer
- (decision) Use FactoryKit exclusively in Coordinator Views as the UI composition boundary, not in View Models or regular Views
- (constraint) Coordinator Views receive individual Use Cases via @Injected(\.someUseCase), not an aggregate
- (constraint) View Models receive Use Cases via constructor injection (init), never @Injected or Container.shared
- (constraint) Regular SwiftUI Views must not know about FactoryKit or DI infrastructure
- (constraint) Domain and Data layers must not depend on FactoryKit
- (constraint) Repositories, APIClient, and Container must never be passed to Views or View Models
- (decision) Delete SwiftUI EnvironmentKey for UseCases and remove .environment(\.useCases, ...) from LexickonApp
- (decision) Replace @Environment(\.useCases) in Coordinator Views with FactoryKit @Injected for individual Use Cases
- (decision) Delete UseCases aggregate if no longer referenced after migration
- (decision) Evaluate AppContainer necessity; delete or simplify if no longer needed after Environment removal
- (decision) Rename ProductionAssembly.makeContainer() if it no longer creates AppContainer
- (decision) Preserve constructor injection in all View Models for testability without global container
- (constraint) Preserve existing app behavior; no changes to repository or Use Case APIs
- (constraint) Repository scopes unchanged in this refactor
- (decision) Use .unique scope for stateless Use Cases in FactoryKit registrations
- (decision) Update DI tests to validate new FactoryKit structure and architectural constraints
- (constraint) Architectural rule: @Injected allowed only in Coordinator Views
- (constraint) Architectural rule: View Models accept Use Cases only through init parameters
- (constraint) Architectural rule: No EnvironmentValues.useCases exists in project after refactor
- (constraint) Architectural rule: UseCases aggregate and AppContainer must be absent if no longer needed
