# Дополнение к PRD Lexickon
*Подробности для архитектуры, UX и историй. Не нужны для принятия PRD. Источник оценки полезности — JEV через прокси на бэкенде Lexickon (ключ у клиента не хранится); платформа — iOS 18.*

---

## A. Решение KR-1: источник полезности

**Решение.** JEV System One — источник для V1. Бэкенд делает один вызов `score` на домен (общий английский плюс каждый выбранный домен) с пятью уровнями, заданными вызывающей стороной: очень высокая, высокая, средняя, ограниченная, низкая полезность. Уровень определяется по оценке (score); уверенность — по возвращённому распределению вероятностей; основание — фиксированное описание уровня; результаты помечаются как оценка модели. Ниже порога уверенности уровень равен `insufficient_data`. Корпусная частота может добавляться как свидетельство для общего английского из датасетов проекта Lemma Atlas.

**Обратимость.** Источник находится за эндпоинтом поиска на бэкенде. Запасной вариант — датасет, который строит проект Lemma Atlas вне этого репозитория на собственных корпусах автора, без сторонних лицензий. Датасет хранится и читается на бэкенде за тем же эндпоинтом (локальное использование на устройстве слишком дорого для первых версий), приложение его не видит. Сигнал меняется с оценки модели на корпусную частоту, поэтому меняется и основание. Деградация: только отдельные слова в доменах с корпусом; фразы и прочие домены — `insufficient_data`; `confidence` может быть null. Это снижение объёма V1, а не равноценная замена (FR-1).

**Что происходит при переключении** (решено 2026-10-04). Переключение — это не техническая подмена, а повод пересмотреть тезис: (1) отличие из §1.0 при запасном варианте не сохраняется, потому что частотный ранг уже есть у Language Reactor, а оценка по домену с уверенностью остаётся только для слов разработки; (2) EX-1 сужается до слов (без фраз), а домены beta по FR-11 ограничиваются теми, для которых у Lemma Atlas есть корпус; (3) EX-3 после переключения измеряет влияние метки частоты, поэтому личный эксперимент повторяется на слове разработки (не менее 50 слов) и решение о beta принимается заново; (4) если EX-3 при этом ниже 20%, проект не запускает beta без нового источника: тезис «оценка по домену до сохранения» не подтверждён ни моделью, ни частотой. Порядок: пилот KR-12 идёт до архитектуры, личный эксперимент после; «повторить эксперимент» относится только к переключению, случившемуся после первого эксперимента.

**Почему.** Проверяемый тезис — решение о полезности, а примитив JEV (выбор / порядковая оценка по уровням, заданным вызывающей стороной) напрямую соответствует пятиуровневой шкале. Он поддерживает фразы и любой домен через переписывание описаний уровней, без создания новых данных до личного эксперимента. Исследование 2026-09-27 не нашло опубликованного контракта корпусной частотности ни у JEV, ни у Laya, поэтому сигнал честен только при пометке «оценка».

**Факты для повторной проверки (из исследования, до 2026-10-27).** Эндпоинт `POST /v1/systemone`; до десяти уровней; цена около $0.042 за 1M входных токенов; 1200 запросов в минуту; рекомендуется закрепить версию модели; дообучение клиентом не документировано; JEV не объясняет свои ответы текстом.

**Заметки по проектированию для архитектуры.**
- Ключ локального кеша (общего кеша в V1 нет, KR-9): нормализованный термин, домен, версия, хеш контекста (если задан). Версию модели закрепить, чтобы закешированные уровни оставались сопоставимыми; запись с другой версией отбрасывается.
- Стоимость растёт с числом доменов в одном поиске; каждый домен засчитывается в лимит поисков на пользователя (KR-6).
- Описания уровней по доменам — конфигурация, версионируется вместе с версией модели.
- Пилот (KR-12) фиксирует порог «данных недостаточно» и проверяет стабильность при повторных вызовах.

**Отклонено или отложено.** Laya: слабее на независимом бенчмарке с одинаковым входом (0.69 против 0.91, это не тест частотности), нагрузка локальной эксплуатации и закрепления версии. Сначала корпус: требует собственного датасета до первого эксперимента; сохранён как запасной вариант (см. «Обратимость»). Основание, написанное LLM: функции LLM вне V1.

### A.1 План пилота KR-12 (JEV против датасета Lemma Atlas)

**Эталон.** Датасет Lemma Atlas даёт частотность слов на миллион токенов. Он принимается как точка истины для отдельных слов, для общего английского и для домена разработки (корпус по разработке существует). Допущение A-3, принятое автором: для этих слов частотность — приближённый эталон полезности, но не потолок (JEV вправе и должен расходиться с ней осмысленно, см. «Ценность сверх частоты»). В датасете пока нет фраз, поэтому фразы вне объёма пилота, а их оценка в V1 остаётся непроверенной (ручная выборка автора не менее 30 фраз, см. «Что пилот не покрывает»).

**Метод.**
1. Взять 100–200 отдельных слов на домен (общий английский и разработка) из реальных материалов для чтения.
2. Преобразовать каждую частотность в одну из пяти точек шкалы полезности по фиксированным диапазонам, заданным по датасету до запуска: диапазоны записывает автор в это приложение до первого вызова JEV и не меняет после; набор диапазонов отдельный для каждого домена, по его корпусу.
3. Отправить те же слова в JEV и сопоставить возвращённый уровень с той же шкалой.
4. Сравнить слово за словом.

**Диапазоны частот** (решено 2026-10-07, до первого вызова JEV формального прогона; после не меняются). Метрика — Zipf по лемме целиком (все части речи вместе), как в индексах Lemma Atlas, которые показывает `tools/lemmaatlas_cli.py`. Границы — нижние, включительно.

| Точка шкалы | Общий английский (Lemma Atlas core 1.0.0) | Разработка (Lemma Atlas programming 0.1.0) |
|---|---|---|
| очень высокая | Zipf ≥ 5.0 | Zipf в домене ≥ 5.0 |
| высокая | 4.0 ≤ Zipf < 5.0 | 4.0 ≤ Zipf в домене < 5.0 |
| средняя | 3.0 ≤ Zipf < 4.0 | 3.0 ≤ Zipf в домене < 4.0 |
| ограниченная | 2.0 ≤ Zipf < 3.0 | 2.5 ≤ Zipf в домене < 3.0 |
| низкая | Zipf < 2.0 | Zipf в домене < 2.5 или слова нет в корпусе домена |

- Эталон для разработки — частота в корпусе разработки, без поправки на специфичность (решено 2026-10-07). Общие слова, частые в документации (например, `think`, `meet`), считаются полезными для разработчика по своей частоте в домене, даже если это не термины. Частота в общем английском и метка специфичности Lemma Atlas записываются в результаты пилота как справка для ручного разбора расхождений, но в критерии не входят.
- Нижняя граница «ограниченной» в разработке поднята до 2.5: в корпусе разработки нет слов с Zipf ниже 2.0, и без этого точка «низкая» была бы пустой.
- Границы совпадают с фиксированными полосами Lemma Atlas (`very_common`+`common`, `mid_frequency`, `uncommon`, `rare`, `very_rare`), кроме объединения двух верхних полос в одну точку и границы 2.5 для разработки.
- Скрипт пилота: `tools/jev-pilot/pilot.py`; версии датасетов записываются в `datasets.json` каждого прогона.

**Отбор слов: отклонение от шага 1 метода** (решено 2026-10-07). Слова берутся не из реальных материалов для чтения, а стратифицированной случайной выборкой из индексов Lemma Atlas: поровну на каждую точку шкалы (при 200 словах на домен — по 40), с фиксированным seed. В выборку попадают только знаменательные части речи (существительное, глагол, прилагательное, наречие по части речи с лучшим рангом), слова из системного словаря английского (`/usr/share/dict/words`, отсекает артефакты корпуса) длиной не менее трёх букв.
- Почему: равные доли проверяют все пять точек шкалы, включая «низкую» и «ограниченную», которых в реальном тексте почти нет; без этого критерий совпадения определялся бы в основном частыми словами.
- Чем платим: редких слов в выборке намного больше, чем при чтении, поэтому доля совпадения не равна точности, которую увидит пользователь на своих поисках; она взвешена по точкам шкалы, а не по встречаемости. Для оценки на реальных поисках остаётся личный эксперимент (EX-3).
- Правило выхода не меняется: повторный прогон после правки описаний уровней идёт на новой выборке тем же способом (другой seed).

**Критерии прохождения.**
- По слову: уровень JEV должен совпасть с точкой датасета на пятиточечной шкале один в один. Если датасет даёт 4, JEV должен дать 4.
- В целом: не менее 80% слов с точным совпадением (решено 2026-10-04). Оба критерия считаются отдельно по каждому домену пилота (общий английский, разработка); провал в любом домене — провал пилота (предложено 2026-10-04).
- Слова, где уровни не совпали, разбираются вручную. Они показывают, ошибся ли JEV или уловил то, чего не отражает частотность (например, редкое, но нужное слово), и пополняют описания уровней.
- **Ценность сверх частоты** (решено 2026-10-04). Совпадение с частотой доказывает только, что JEV не хуже частотного словаря; оправдать вызов внешнего сервиса может лишь то, что он добавляет. Поэтому из слов с расхождением берётся выборка не менее 20 слов. Если расхождений меньше 20, набор слов увеличивается до 400 на домен; если и тогда их меньше 20, JEV почти не отличается от частоты и ничего не добавляет, что приравнивается к провалу критерия. Автор вслепую, не видя, какая оценка чья, выбирает для каждого слова одну из трёх позиций: оценка JEV точнее, оценка по частоте точнее, равноценно. «Равноценно» входит в знаменатель. JEV проходит критерий, если его оценку выбрали не менее чем в 70% слов выборки. Иначе источник переключается на Lemma Atlas по правилу выхода: платить за внешний сервис, который не даёт ничего сверх частоты, нет смысла. Критерий проверяет суждение одного автора на небольшой выборке, поэтому это сигнал, а не статистическое доказательство.

**Окно прохождения** (решено 2026-10-04). Два критерия вместе задают окно по доле совпадения уровня с частотой: нижняя граница 80%, верхняя — доля, при которой ещё остаётся 20 расхождений для выборки ценности: 1 − 20/N, где N — число слов домена. Для 100 слов окно — ровно 80%, для 200 — 80–90%, для 400 — 80–95%. Совпадение выше окна означает, что JEV почти не отличается от частоты и ничего не добавляет (после добора до 400 слов): это провал критерия «ценности сверх частоты» и повод для переключения на Lemma Atlas по правилу выхода. Размер набора поэтому выбирается заранее: по умолчанию 200 слов на домен (окно 80–90%), добор до 400 только если расхождений меньше 20.

**Шкала.** Пять точек — в продукте так же, как и в пилоте (решено 2026-10-04): очень высокая, высокая, средняя, ограниченная, низкая. JEV поддерживает до десяти уровней, поэтому вызывается с пятью описаниями уровней.

**Прочие проверки.** Задержка p95; стабильность при повторных вызовах (не менее 95% повторов дают тот же уровень, иначе провал, допущение A-4); порог уверенности для «данных недостаточно»; обработка значений слова через контекстное предложение (не менее 10 пар многозначных слов с разными контекстами, уровни различаются не менее чем в 7 парах; рабочие значения); сравнение с универсальной LLM не проверяется до beta: риск «зачем платить за JEV, если можно спросить LLM» принят осознанно (KR-3 отложен, решено 2026-10-04).

**Что пилот не покрывает.** Фразы и домены, кроме разработки (в том числе «science», «бизнес», «медицина» для beta): эталона для них нет. Оценки фраз проверяет автор на ручной выборке (не менее 30 фраз) в личном эксперименте; для доменов beta эталон появляется, когда Lemma Atlas получит соответствующие корпуса. До этого оценки таких доменов остаются непроверенными (допущение A-1).

**Правило выхода.** Если любой из критериев прохождения (совпадение с частотой, ценность сверх частоты или стабильность при повторных вызовах, A-4) не выполнен после одного раунда переписывания описаний уровней (повторный прогон идёт на новой выборке слов, чтобы описания не подгонялись под прежнюю), источник переключается на датасет Lemma Atlas (KR-1).

### A.2 Результаты пилота KR-12

**Формальный прогон 1 (2026-10-07).** JEV `jev-1.13.0`; эталон Lemma Atlas core 1.0.0 и programming 0.1.0; описания уровней первой редакции (в скрипте); 200 слов на домен по правилам отбора §A.1, по три вызова на слово; данные — `_bmad-output/planning-artifacts/pilot-kr12/run-2026-10-07/`.

| Показатель | Общий английский | Разработка | Критерий |
|---|---|---|---|
| Точное совпадение уровня с частотой | 34% | 26% | 80–90%: не пройден |
| Совпадение с точностью до одного уровня | 83% | 82% | — |
| Связь порядка с частотой (Spearman, средний score) | 0.82 | 0.78 | — |
| Стабильность повторов (A-4) | 95% (190/200) | 95% (190/200) | ≥ 95%: пройден на границе |
| Расхождений для слепой оценки | 133 | 147 | ≥ 20: достаточно |
| Задержка одного вызова | медиана 1.02 с, p95 1.15 с | | вендор заявляет 0.07–0.5 с |

- JEV систематически занижает уровень (в среднем на −0.56 и −0.55 точки). Потолок любой перекалибровки границ на шкале score JEV (лучшие четыре порога при текущих описаниях) — 56% и 55%, то есть сдвиг границ правкой описаний уровней до 80% не доводит; дотянуть может только изменение самого порядка ответов.
- В разработке JEV не различает нижнюю половину шкалы: средний score для точек «низкая», «ограниченная», «средняя» — 0.98, 0.97, 1.21; 96 из 120 таких слов отнесены к «ограниченной». Термины с высокой специфичностью (15 слов) JEV оценивает ниже частоты в среднем на одну точку, а не выше.
- Ценность сверх частоты (слепая оценка) ещё не проверена.

**Проверка эталона независимым источником (2026-10-08).** Чтобы исключить вывод по ошибочному эталону, Lemma Atlas core сравнён с `wordfreq` 3.1.1 (открытый частотный словарь английского по субтитрам, Википедии, новостям, книгам и вебу; шкала Zipf) по тем же порогам. `wordfreq` считает словоформы, поэтому сравнение сделано двумя способами: форма с формой (`core_surface_frequency.parquet`) и лемма с леммой (частота леммы по `wordfreq` собрана из её словоформ по таблице Lemma Atlas, общие формы разделены пропорционально).

| Сравнение | Слов | Spearman | Точно по уровню | ±1 уровень |
|---|---|---|---|---|
| Lemma Atlas — `wordfreq`, форма с формой | 2000 (по 400 на точку) | 0.955 | 73% | 99% |
| Lemma Atlas — `wordfreq`, лемма с леммой | 2000 (по 400 на точку) | 0.952 | 72% | 99% |
| Lemma Atlas — `wordfreq`, лемма с леммой | 200 слов прогона 1 | 0.941 | 62% | 98% |
| JEV — Lemma Atlas | 200 слов прогона 1 | 0.82 | 34% | 83% |

**Находка** (2026-10-08).
1. Lemma Atlas пригоден как эталон: с независимым источником порядок слов почти тот же, расхождение больше одной точки — 1–2% слов.
2. Порог точного совпадения 80% недостижим и для эталона: два независимых частотных источника совпадают по точке шкалы в 62–73% слов (слова около границы точки неизбежно расходятся на соседнюю). При этом пороге пилот не прошёл бы и частотный словарь. Это основание пересмотреть формулировку критерия, полученное на независимом источнике, а не на ответах JEV.
3. Вывод о JEV от этого не меняется: JEV согласуется с частотой заметно хуже, чем частотные источники между собой (34% против 62–73% точно, 83% против 98–99% в пределах одной точки), то есть не проходит и относительную планку «не хуже согласия источников».
4. Дефект выборки: в Lemma Atlas имена собственные с частотой под леммой с заглавной буквы оставляют редкие остатки в нижнем регистре (`december`, `jones`; в прогоне 1 — `ethel`, `madonna`, `stockbridge`), и фильтр отбора их пропускает. На вывод о JEV не влияет (без 35 слов с расхождением эталонов больше 1 Zipf совпадение JEV — 30%), но следующую выборку от них нужно очищать.
5. Домен разработки независимым источником не проверен: открытого частотного словаря по программной документации нет; проверка требует подсчёта по другому корпусу документации.

**Что не решено.** Пересматривать ли критерий совпадения (например, на относительную планку от согласия источников); слепая оценка расхождений; раунд правки описаний уровней по правилу выхода.

### A.3 Пилот фраз в домене разработки (план, записан до прогона 2026-10-08)

**Зачем.** На отдельных словах JEV не заменяет частоту (§A.2), но для фраз частотного источника у проекта нет: Lemma Atlas многословные выражения не считает. Пилот проверяет, даёт ли JEV для фраз пользу, которой иначе нет. Вопрос поставлен после результатов на словах; критерии ниже записаны до первого вызова JEV на фразах и после прогона не меняются.

**Шкала пилота — три точки** (высокая, средняя, низкая полезность). Свёртка пяти уровней в три на данных §A.2 подняла совпадение JEV со словами до 50–60% (потолок перекалибровки 70–75% против 79–80% у двух частотных источников), поэтому для фраз проверяется трёхточечная шкала. Это решение только для пилота: шкала продукта (пять точек, решено 2026-10-04) не меняется, пока нет результата.

**Эталон частоты.** Частота фразы (2–3 слова, словоформы, внутри сегмента) по очищенным текстам корпуса разработки Lemma Atlas programming 0.1.0 (`data/domains/programming/cleaned/*/clean_segments.jsonl`, около 5 млн слов), с теми же весами источников, что у Lemma Atlas для слов (документация 0.35, README 0.25, Stack Overflow 0.25, книги 0.15). Скрипт `tools/jev-pilot/phrases.py`; данные `_bmad-output/planning-artifacts/pilot-kr12/phrases-programming/`.

| Точка | Zipf фразы в корпусе разработки |
|---|---|
| высокая | ≥ 4.0 (не реже 10 раз на миллион слов) |
| средняя | 3.4 ≤ Zipf < 4.0 |
| низкая | < 3.4 (нижняя граница корпуса около 2.9: не меньше 5 употреблений) |

**Эталон устойчивости.** NPMI сочетания по тому же корпусу (для триграмм — минимум по двум разбиениям): устойчивое — NPMI ≥ 0.5, свободное — NPMI < 0.3 (зазор, чтобы классы не сливались). Это статистическое приближение: оно считает устойчивыми и названия, поэтому названия продуктов и код вычеркнуты из выборки (ниже). Разметка автором вместо NPMI не выбрана.

**Выборка.** Кандидаты: сочетания из 2–3 слов, не меньше 5 употреблений и двух источников из четырёх; без служебного слова в начале и в конце (кроме частицы фразового глагола после глагола: `figure out`, `turn it off`); слова из словаря английского в нижнем регистре или частые в домене (Zipf ≥ 3.0) и не имена собственные. Из 23 592 кандидатов случайно (seed 12) по 25 фраз в каждой клетке «точка × устойчивое/свободное», всего 150. До вызовов JEV вручную вычеркнуты 39 фраз — код (`sys argv`, `const char`), названия продуктов (`react native`, `big sur`), обрывки на стыке слов и предложений (`hand side`, `git hub`) — и заменены случайными из той же клетки; список с причинами — `excluded.tsv`.

**Вопросы к JEV** (описания уровней и формулировки фиксируются в скрипте до прогона; по три вызова на фразу).
- (а) Полезность фразы для разработчика, читающего документацию и обсуждения, — `score` с тремя описаниями уровней.
- (б) «Это устойчивое выражение, которое стоит учить целиком как единицу, а не по отдельным словам?» — вероятность «да».

**Базовое правило для сравнения** (бесплатное, из Lemma Atlas): оценка фразы — частота её самого редкого слова в индексе Lemma Atlas programming (по лемме, с грубым приведением словоформ). JEV имеет смысл, только если он лучше этого правила.

**Критерии прохождения** (на 150 фразах).
- (а) Порядок: Spearman между средним score JEV и Zipf фразы выше, чем у базового правила, не меньше чем на 0.05.
- (а) Точки шкалы: JEV и базовое правило переводятся в три точки одинаково — по долям эталона (50 фраз с наибольшей оценкой — высокая, следующие 50 — средняя, остальные — низкая). JEV совпадает с эталоном чаще базового правила и не менее чем в 60% фраз (случайное совпадение — 33%).
- (а) Грубые ошибки (высокая против низкой) — не больше 10% фраз.
- (б) Вероятность «да» отделяет устойчивые сочетания от свободных: AUC не ниже 0.80 (0.5 — случайность, 1.0 — идеальное разделение).
- Стабильность: не менее 95% фраз получают одинаковый ответ во всех трёх повторах — в (а) точку шкалы, в (б) ответ «да/нет» по порогу 0.5.

**Что решает результат.** (а) и (б) пройдены — JEV остаётся кандидатом на оценку фраз (роль и шкала продукта решаются отдельно, вместе с решением по словам). Пройден только (б) — JEV кандидат на признак «учить целиком», без уровня полезности. Не пройдены оба — фразы в V1 без оценки полезности (`insufficient_data`), а их полезность остаётся непроверенной (A-1).

**Что пилот не покрывает.** Фразы общего английского: текстов корпуса core в Lemma Atlas нет, только агрегированные счётчики; внешний эталон (например, Google Books Ngram) не выбран.

**Результаты (прогон 2026-10-08).** JEV `jev-1.13.0`, 150 фраз, по три вызова; данные и полный отчёт — `_bmad-output/planning-artifacts/pilot-kr12/phrases-programming/` (`report.md`).

| Критерий | Результат | Итог |
|---|---|---|
| (а) Spearman JEV выше правила «самое редкое слово» на 0.05 | 0.389 против 0.281 (+0.107) | пройден |
| (а) Совпадение точки ≥ 60% и выше правила | 45% против 42% | не пройден |
| (а) Грубые ошибки ≤ 10% | 11% | не пройден |
| (б) AUC «устойчивое выражение» ≥ 0.80 | 0.705 | не пройден |
| Стабильность (а) ≥ 95% | 94% | не пройден |
| Стабильность (б) ≥ 95% | 98% | пройден |

Задержка: медиана 0.60 с, p95 0.83 с. По правилу «Что решает результат» не пройдены оба вопроса.

**Находки.**
1. Частоту фраз JEV почти не различает: средний score для точек низкая / средняя / высокая — 1.13 / 1.31 / 1.48. Расхождения систематические: JEV оценивает, термин ли это, а не частоту (`strict equality operator`, `opening bracket` — редкие в корпусе, у JEV высокие; `other way`, `exist on` — частые, у JEV низкие).
2. Эталон устойчивости (NPMI) ошибается в обе стороны, поэтому AUC 0.705 занижен на неизвестную величину. NPMI назвал свободными настоящие термины и фразовые глаголы, которые JEV уверенно считает устойчивыми (`query string` 0.93, `merge commit` 0.92, `call signature`, `floating point value`, `line number`, `turn on`), и устойчивыми — обычные сочетания, которые JEV отвергает (`slightly differently` 0.09, `five million`, `relatively expensive`, `days ago`, `easier to read`). Результат по предзаписанному критерию не пересматривается; проверка вопроса (б) с эталоном-разметкой автора на новой выборке возможна отдельным предзаписанным прогоном и пока не решена.

### A.4 Решение после пилота KR-12 (2026-10-08)

**Решение автора.** Пилот KR-12 не пройден ни на словах (§A.2), ни на фразах (§A.3), и по правилу выхода (§A.1) источник должен был переключиться на Lemma Atlas. Автор осознанно отступает от этого правила: MVP оценивает полезность слов и фраз через JEV. Причина — так проще запустить первую версию; переход на Lemma Atlas запланирован.

**Принятый риск.** Пользователь видит оценки, которые пилот измерил как ненадёжные: точное совпадение с частотой 34% и 26% на словах (5 точек), грубые ошибки 11% на фразах. Поэтому оценка в интерфейсе — только «оценка модели» (`estimate` = true, формулировка «ориентир»), без выдачи её за частоту. В личном эксперименте в журнале отмечаются случаи, когда оценка явно расходится с суждением автора: EX-3 при шумном сигнале меряет и влияние ошибок.

**Устройство.** Источник оценки — отдельный сервис на бэкенде за общим интерфейсом источника (§H). В MVP — сервис JEV. Запланированная замена — сервис на SQLite-пакетах Lemma Atlas (core и доменные), который читает бэкенд; приложение от смены источника не зависит (контракт D не меняется, меняются значения `estimate`, `basis`, `confidence`, `version`; деградация запасного варианта — §A «Обратимость»).

**Когда переходить.** Решение о переходе на Lemma Atlas принимается до beta (20–30 пользователей), по итогам личного эксперимента. Фразы на Lemma Atlas остаются без оценки (`insufficient_data`), пока нет частотной модели фраз.

## B. Детали алгоритма SRS (для архитектуры и историй)

*V1: простой SM-2 без модификатора сложности от LLM (KR-2, KR-11). Значения ниже — рабочие; параметры поступают из удалённой конфигурации.*

### Расписание
- Первое успешное повторение — через 1 день, второе — через 6 дней; далее `интервал = предыдущий интервал * коэффициент лёгкости`, с округлением вверх до целых дней.
- Коэффициент лёгкости: начальное значение 2.3, диапазон [1.3, 2.5], обновляется после каждой оценки.
- Unknown — провал: счётчик повторений обнуляется, интервал возвращается к 1 дню, `lapses` растёт на 1.
- Poor — не провал: интервал не растёт, счётчик повторений не меняется.
- Good и Excellent — успех: счётчик повторений растёт, интервал считается по формуле.

### Оценка → изменение коэффициента лёгкости
| Оценка | Изменение коэффициента лёгкости |
|--------|---------------------------------|
| Unknown | -0.2 |
| Poor | -0.05 |
| Good | 0.0 |
| Excellent | +0.05 |

### Обработка лейчей
- `lapses > 3` → карточка помечается как «Лейч»
- Лейчи: интервал сбрасывается до 1 дня, коэффициент лёгкости = 1.3 (один раз, в момент пометки), показываются в конце сессии; `lapses` продолжает считаться
- Пользователь может отложить лейч (перенести в колоду отложенных); при возврате из отложенных `lapses` обнуляется, и карточка перестаёт быть лейчем

## C. Модель данных (для архитектуры и историй)

### Flashcard (SwiftData / SQLite)
```swift
struct Flashcard {
  let id: UUID
  var front: String              // целевой термин/фраза
  var normalizedFront: String    // front в нижнем регистре, без лишних пробелов; индексируется для проверки «Уже в вашей колоде» (FR-16)
  var backTranslation: String
  var exampleSentences: [String] // 1-2
  var assessments: [DomainAssessment]?  // снимок оценок при создании; nil для карточек, созданных вручную
  var sourceQuery: String?       // исходный запрос; nil для карточек, созданных вручную
  var source: Source             // .lookup | .manual
  var createdAt: Date
  var srs: SRSMetadata
}

struct DomainAssessment {
  var domain: String
  var level: Level               // very_high | high | medium | limited | low | insufficient_data
  var confidence: Double?        // nil только при запасном варианте KR-1 (частота без собственной уверенности); UI скрывает строку уверенности
  var basis: String              // производное от level и version (при JEV — фиксированный текст уровня); при запасном варианте — «частота N на млн, корпус, версия»
  var estimate: Bool             // true: оценка модели (JEV); false: корпусный подсчёт (запасной вариант)
  var version: String            // версия источника на момент снимка: карточки до и после смены источника различимы
}

struct SRSMetadata {
  var intervalDays: Int          // 0 = новая
  var easeFactor: Double         // 1.3 - 2.5, начальное 2.3
  var repetitions: Int           // успешные повторения
  var lapses: Int                // сколько раз оценено как Unknown
  var isNew: Bool                // true до первой оценки
  var firstShownAt: Date?        // когда впервые введена в сессии; учитывается в дневном лимите новых карточек
  var nextReviewDate: Date
  var lastRating: Rating?        // для подсчёта серий
}
```

### Кеш поиска
```swift
struct CachedAssessment {
  let normalizedTerm: String     // нормализованный (нижний регистр, без пробелов по краям)
  let domain: String
  let contextHash: String?       // nil, если контекст не задан; сам контекст не хранится
  let version: String            // версия модели JEV вместе с версией описаний уровней
  let assessment: DomainAssessment
  let translation: String?       // перевод термина из того же ответа (общий для всех доменов запроса, дублируется в записях), чтобы офлайн-попадание в кеш не теряло перевод (FR-2, FR-3)
  let cachedAt: Date
  let expiresAt: Date            // cachedAt + 30 дней
}
```

## F. Отклонённые альтернативы (для журнала архитектурных решений)

| Альтернатива | Причина отклонения |
|-------------|---------------------|
| Оставить пакеты SQLite и добавить JEV как запасной вариант | Двойная нагрузка на сопровождение; пакеты устаревают; сложность синхронизации сохраняется. | Сложность от LLM и генерация карточек LLM в V1 | Отложено 2026-09-30 (KR-11): проверяемый тезис — решение о полезности; функции LLM добавляют расходы и неопределённого провайдера (KR-3). Могут вернуться после beta |
| Синхронизация колоды через CloudKit (V1) | Расширение объёма; локальный подход проще; конфликты синхронизации с расписанием SRS требуют решения |
| Одна бинарная оценка «Знаю/Не знаю» | Теряется градиент сигнала для SRS; 4 оценки — стандарт для адаптивных алгоритмов |

## H. Детали для архитектуры и историй

**Проверка «Уже в вашей колоде» (FR-16).**
- Ссылка на существующую карточку разрешается в момент нажатия. Если карточку тем временем удалили, уведомление исчезает, а не ведёт в пустоту.
- Если совпадает несколько карточек (дубль создан осознанно через «Создать ещё одну»), ссылка открывает самую свежую.

**Источник оценки полезности — заменяемый сервис** (решено 2026-10-08, §A.4).
- Бэкенд обращается к источнику оценки через один внутренний интерфейс: на входе нормализованный термин, домен, контекст (если задан); на выходе по каждому домену уровень, уверенность (может быть null), основание, признак `estimate` и версия источника. Эндпоинт поиска и контракт D от реализации не зависят.
- MVP: сервис JEV (ключ только на бэкенде, `score` с описаниями уровней по доменам; описания уровней версионируются вместе с моделью). Домены опрашиваются параллельно: задержка одного вызова JEV по пилоту — медиана 0.6–1.0 с, p95 0.8–1.2 с (вендор заявляет 0.07–0.5 с).
- Запланированная замена: сервис на SQLite-пакетах Lemma Atlas (`core_frequency_index.sqlite`, `programming.sqlite`; таблицы `core_lemma`, `domain_lemma`), который читает бэкенд. Пороги перевода частоты в уровни — §A.1 «Диапазоны частот»; фразы — `insufficient_data`.
- Переключение источника — конфигурация бэкенда, а не изменение приложения; версия источника входит в ключ локального кеша (FR-8), поэтому старые записи после смены источника отбрасываются.
