- (decision) Одобрен standard-run: техническое сравнение двух кандидатов; критерии — семантика метрики, качество, стабильность, интеграция и экономика; topology depth-first, три независимых исследовательских угла.
- (source) Source batch: TypeSafe official System One, Score, Models docs; Laya official repo/model card; SUBTLEX-US; wordfreq code; sysone-bench independent benchmark.
- (claim) ref=[1] status=verified class=capability pub=2026-09 — Jev exposes typed decision primitives, not a corpus-frequency endpoint.
- (claim) ref=[2] status=verified class=metric-semantics pub=2026-09 — Jev Score is an expectation over caller-defined ordinal level indices, not an arbitrary measured numeric quantity.
- (claim) ref=[4] status=verified class=capability pub=2026-09 — Laya exposes choice, score, and noul; no native corpus-frequency output is documented.
- (claim) ref=[4] status=verified class=quality pub=2026-09 — Laya maintainers describe base checkpoints as a base to specialise and disclose weak zero-shot task transfer.
- (claim) ref=[6] status=verified class=benchmark pub=2026-09 — Independent same-input classification benchmark favors Jev 0.9065 over Laya 0.6863, but does not test frequency.
- (claim) ref=[7] status=verified class=measurement pub=2009-01 — Frequency per million is a normalized observed corpus count; contextual diversity is a separate useful measure.
- (claim) ref=[9] status=verified class=implementation pub=2026-09 — wordfreq multi-token values use a reciprocal-sum token heuristic rather than observed phrase counts.
- (claim) ref=[10] status=verified class=license pub=2026-09 — Laya model and code are published under Apache-2.0.
- (event) Research complete. Verdict: neither Jev nor base Laya has a published corpus-frequency contract; recommend versioned corpus lookup as source of truth and Laya only as validated estimated-commonness fallback. Citation audit passed after narrowing API-compatibility and undocumented-capability wording.
